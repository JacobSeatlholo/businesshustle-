1 Executive Summary

ScamCheck MVP demonstrates a clear concept — helping users verify whether a website, link, or seller is a scam — but in its current form it is not a product, it is a prototype. There is no user authentication, no persistent data, no monetization layer, no trust signaling, and no retention mechanism. The core checking logic appears superficial, and the site lacks the depth and credibility that the subject matter (fraud detection) demands. Without significant investment in data depth, user trust, and recurring value, this will not generate revenue.

Key Takeaways

  • The biggest blocker is credibility. A scam-checking tool that doesn't itself look trustworthy is self-defeating. The MVP needs professional design, clear data sources, and transparency about methodology.
  • There is no moat. Without proprietary data, API integrations, or user-generated intelligence, any competitor can replicate this in a weekend.
  • Monetization is impossible without depth. Users won't pay for superficial checks. Depth of analysis = willingness to pay.
  • The market is real and growing. Global online fraud losses exceeded US$10 billion in 2023 (FTC, United States). Locally, South Africans lost billions to scams and cyber fraud in the same period. There is genuine demand — but the bar for trust is extremely high.

2 Current State Analysis

What Exists Today

  • Landing page with a basic input field for URLs/text
  • Simple check logic — appears to perform basic pattern matching or surface-level analysis
  • Result display — shows a risk score or flag
  • Deployed on Vercel — fast hosting, but no backend infrastructure
  • No authentication — anonymous, session-less usage
  • No database — no history, no persistence, no learning
  • No payment integration

Strengths to Build On

Clear value proposition

"Is this a scam?" is a question everyone understands. No education needed.

Fast deployment

Vercel hosting means near-zero infrastructure cost and global edge performance.

Massive addressable market

Consumers, small businesses, elderly users, gig workers — everyone is a potential user.

Weaknesses That Kill Profitability

No data moat — checks are shallow

If the "scam check" is just checking domain age or a regex pattern, it provides near-zero value over a Google search. Users will see through this instantly.

Critical

Zero retention mechanics

User visits, checks one URL, leaves forever. No account, no history, no reason to return. CAC > LTV is guaranteed.

Critical

Credibility gap

A fraud-detection tool must look and feel more trustworthy than the scams it detects. The current design doesn't meet that bar.

Critical

No community or network effects

The most valuable scam data comes from victims. Without user reporting, the database will always be stale and incomplete.

3 Critical Issues (P0) — Revenue Blockers

These issues must be resolved before any monetization attempt. Each one independently prevents profitability.

No User Accounts or Identity

Without authentication, you cannot: charge users, save history, build profiles, offer subscriptions, or track retention. This is the single most important missing piece.

P0

Analysis Engine is Superficial

A scam checker is only as good as its data. If the engine only checks surface signals (domain age, HTTPS presence), the results are trivially replicable and often wrong. You need multi-layered intelligence: domain reputation APIs, blacklists, content analysis, social signals, user reports, and pattern databases.

P0

No Payment Infrastructure

Zero integration with Yoco, Paystack, Stripe, or any payment provider. No pricing page, no billing logic, no free/paid tier differentiation. For a South African launch, Yoco or Paystack are the practical defaults for local card + EFT support.

P0

No Trust or Transparency

Users need to see why something is flagged. "This looks suspicious" with no explanation is worse than useless — it's actively harmful. Every result must cite sources, show reasoning, and provide confidence levels.

P0

No Data Persistence or History

Without a database, every check is isolated. No trending, no "recently flagged," no learning from past checks. The system can't improve because it has no memory.

P0

4 UX / Product Gaps

Design & Credibility Issues

  • Visual authority is missing. The site needs to feel like a security product — think VirusTotal, not a side project. Professional typography, structured data display, security badges, and partner logos all signal legitimacy.
  • No explanation of methodology. Users must be able to click "How does this work?" and see a transparent breakdown of every signal checked.
  • No "verified safe" outcome. Only showing risk creates anxiety. A clear "This site is verified safe" with supporting evidence is equally important.
  • Results page lacks depth. A single score isn't enough. Show: domain info, blacklist status, content analysis, user reports, similar known scams, and recommended actions.

5 Technical Architecture — Full System Design

Below is the complete architecture needed to transform the MVP into a scalable, profitable system.

Frontend Layer

Next.js 14+ — App Router, SSR, API routes
Tailwind CSS — Rapid, consistent styling
TanStack Query — Server state management
Shadcn/ui — Professional component library

Backend & API Layer

Next.js API Routes or separate Express/Fastify service
BullMQ + Redis — Job queue for deep scans
Auth.js / NextAuth — OAuth + credential auth
Rate limiting — Upstash Redis ratelimit

Database Layer

PostgreSQL (Neon/Supabase) — Users, checks, reports
Redis (Upstash) — Caching, sessions, queues
Meilisearch / Typesense — Fast search across reports
ClickHouse (optional) — Analytics at scale

Intelligence / Scanning Engine

This is the core differentiator. The scanning engine must aggregate multiple signal sources:

  1. Domain Intelligence — WHOIS data, domain age, registrar reputation, DNS records (use WhoisXML, DomainAge API)
  2. Blacklist Aggregation — Cross-reference Google Safe Browsing, PhishTank, URLhaus, Spamhaus, VirusTotal
  3. Content Analysis — Headless browser (Playwright) to screenshot, extract text, check for clone patterns, compare against known scam templates using NLP similarity
  4. Social Signals — Search for the domain/brand on social media, check Reddit, Twitter/X mentions for scam reports
  5. SSL/TLS Analysis — Certificate validity, issuer reputation, certificate age
  6. User Reports — Community-submitted flags with verification workflow
  7. Pattern Database — Known scam templates, common phishing patterns, fake e-commerce indicators
  8. AI Classification — Fine-tuned model (or prompted LLM) to classify sites based on extracted content and metadata

Infrastructure & DevOps

Vercel — Frontend + API deployment
Fly.io / Railway — Background workers
Resend — Transactional email
Yoco / Paystack / Stripe — Payments

6 Data & Intelligence Engine — The Core Value Multiplier

Signal Architecture

Each check should produce a structured "ScamCheck Report" with the following sections:

Signal Category Data Points Weight
Domain Reputation Age, registrar, WHOIS privacy, DNS anomalies 20%
Blacklist Status Presence on 10+ blacklists 25%
Content Analysis Clone detection, keyword patterns, image reversal 20%
SSL Security Valid cert, trusted issuer, HSTS 10%
User Reports Community flags, verified victim reports 15%
Social Signals Mentions, sentiment, Reddit complaints 10%

Scoring System

  • 0-15: Safe — Verified legitimate, no risk signals
  • 16-40: Low Risk — Minor concerns, proceed with normal caution
  • 41-65: Suspicious — Multiple yellow flags, investigate before engaging
  • 66-85: High Risk — Strong indicators of fraud, avoid
  • 86-100: Confirmed Scam — Actively malicious, appears on blacklists or matches known scams

Data Flywheel

The system becomes more valuable with every user. Here's the virtuous cycle:

  1. User checks a URL → result stored in database
  2. User reports a scam → added to flagged database after verification
  3. More data → better detection accuracy
  4. Better accuracy → more users trust the platform
  5. More users → more reports → more data (loop)

9 Growth & User Acquisition

Organic Channels (High ROI)

  • SEO for scam lookups: Create indexed pages for every checked domain (e.g., scamcheck.app/report/example.com). Target "[brand name] scam" long-tail keywords — these have massive search volume.
  • Shareable report links: Every check produces a unique URL that can be shared on social media, Reddit, forums. "I checked this on ScamCheck — it's a confirmed scam. See: scamcheck.app/report/xyz"
  • Content marketing: "Top 10 scams this week", "How to spot a fake online store", seasonal scam roundups (tax season, holidays)
  • Reddit / forum presence: Helpful, non-spammy replies in r/Scams, r/personalfinance, etc.

Paid Channels (Controlled Scale)

  • Google Ads: Target "is [brand] legit", "[brand] scam", "check website scam" keywords
  • Social media: Short-form content showing scam detections (TikTok, Reels, Shorts) — high viral potential
  • Influencer partnerships: Consumer protection / personal finance YouTubers and TikTokers

Partnership Channels

  • Banks & fintechs: White-label scam checking for their customers (e.g., "Check before you pay" button in banking apps)
  • Marketplaces: Integrate scam checking into platforms like eBay, Craigslist, Facebook Marketplace
  • Elder care organizations: Seniors are the #1 fraud target — partner with AARP, elder care providers
  • Consumer protection agencies: Data partnerships with FTC, CFPB, Action Fraud (UK)

Viral Mechanics

Share-to-Unlock

After a free check, users can share the result on social media to unlock a second free check (or detailed report). Each share = free marketing + new user acquisition.

ScamCheck Verified Badge

Verified businesses embed a badge on their site linking back to ScamCheck. Every legitimate site becomes a permanent inbound link and credibility signal.
